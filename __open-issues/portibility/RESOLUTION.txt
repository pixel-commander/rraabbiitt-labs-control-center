SEARCH WORKER AND VECTORS - PASS
The API reuses a Python worker. Source model/checkpoint changes restart it.
Every request reads the current database export and approved lesson files.
Catalog vectors are keyed by searchable content, record order/identity and
encoder configuration. Disposable vectors are saved under .tmp/hybrid-search.
Full catalog metadata changes also invalidate the in-memory result state.
Tests verified warm worker reuse, changed text rebuilding vectors, changed
instructions reusing vectors, recovery after invalid input, and disk reuse
after a worker restart. Closing the MCP handler stops its search workers.

Measured here with 262 records:
- Vector construction, including field index setup: about 2.2 seconds.
- First cold search: about 11.9 seconds, including model loading.
- Warm repeated search: about 0.4 seconds.
- Restart with saved vectors: about 10 to 12 seconds, mostly model loading.
These are local measurements, not a performance guarantee for enterprise data.
Refresh the catalog after existing source files change. A file edit that is
not indexed cannot invalidate the database-derived vectors.
